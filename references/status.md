# 阶段：状态查看（status）

扫描当前项目 `.sdlc/` 下的阶段产物，汇总研发进度到哪一步。纯只读，不产生任何文件。

## 输入

- 无参数：汇总全部阶段。
- 带参数（如 `design` / `review` / `deploy`）：只展示该阶段。
- 带具体文件路径：读取并展示该产物摘要。

## 前置检查

- 无需探测项目画像。
- 若项目根没有 `.sdlc/` 目录 → 告诉用户当前项目还没走过任何 SDLC 阶段，建议先跑 `sdlc init` 做前置准备（codegraph + 文档整理），再从 `sdlc clarify` 开始。

## 执行

扫描 `.sdlc/` 下的数字前缀阶段目录：

```bash
ls -d .sdlc/*/ 2>/dev/null
find .sdlc -maxdepth 2 -name "*.md" -not -path "*/_archive/*" 2>/dev/null | sort
```

对每个找到的产物，读顶部元信息块拿到 **状态** 字段，推断阶段进展：

- `00-context/` → 上下文资料库（架构文档/知识库等，非流程产物；有则提示"已有 N 份背景资料"）
- `01-prd/` → 需求文档 PRD（已澄清 / 待确认）
- `02-design/` → 方案设计（待评审 / 已评审）
- `03-review/` → 设计评审（通过 / 有条件通过 / 不通过）
- `04-code/` → 编码（有 impl-notes 视为已实现说明）
- `05-test/` → 测试（看测试计划与结果）
- `06-deploy/` → 上线计划（待评审 / 已通过 / 已上线）
- `<数字>-report/` → 统计/分析报告类文档，目录名与文件名均数字前缀开头（如 `07-report/`；独立于主流程，按需存在）
- `_archive/` → 已归档需求，**不计入进度**；仅在末尾提示一句"另有 N 个已归档需求（见 `.sdlc/_archive/`）"

多需求（`.sdlc/<slug>/...` 子目录）时，按需求分组展示。

扫描时留意**流程门禁状态**：若 `03-review` 结论非「通过」却已有 `04-code` 产出，或缺 `01-prd`/`02-design` 却已进入后续阶段，在摘要里以 ⚠️ 标出「跳过了前置阶段」。

## 产出

只在终端输出摘要，不写文件。格式示例：

```
📋 SDLC 进度 —— <项目名>
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📚 00 上下文资料 .sdlc/00-context/                        3 份背景资料
✅ 01 需求文档PRD .sdlc/01-prd/00-用户登录.md              已澄清
✅ 02 方案设计   .sdlc/02-design/00-用户登录.md            已评审
⚠️ 03 设计评审   .sdlc/03-review/00-用户登录.md            有条件通过（2 个 P1）
⬜ 04 编码       —— 尚未开始
⬜ 05 测试       —— 尚未开始
⬜ 06 上线计划   —— 尚未开始
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
下一步建议：处理评审的 2 个 P1 风险，评审转为「通过」后方可进入 code 阶段。
```

## 交接

根据进度给一句下一步建议（哪个阶段该做了、有无阻塞风险），但不自动执行——等用户明确指令。
