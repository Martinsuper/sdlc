# sdlc 产品后续功能规划（v2.0）

> 版本：v2.0-planning · 日期：2026-07-16
> 作者视角：AI Agent 产品经理
> 定位：**开源社区驱动** · 覆盖：**未来 4 季度详细路线图**
> 对象产品：`sdlc` —— AI 驱动的全流程 SDLC 编排 CLI（当前 v1.0 GA）

---

## 这份文档是什么

这是一套**从现状洞察到可执行路线图**的完整产品规划文档集。它回答一个问题：

> **一个已经 GA 的 AI SDLC 编排工具，下一步该往哪走、怎么走、如何证明走对了？**

它不重复已有的 PRD（`prd/`）与设计稿（`doc/design/`），而是站在它们之上，做**前瞻规划**。

---

## 一分钟结论

1. **现状**：产品地基极其扎实（7 抽象、13 包、22 Adapter、548 规则、965 测试、多 LLM），但**端到端主路径当前实测 100% 失败**（P0：temperature 硬编码、错误吞没），且在"agent 智能"与"团队协作"两个决定天花板的维度上是最低分。
2. **北极星**：**周活跃可信 Pipeline 数**（跑完 + 被人类采纳），同时约束用量与质量。
3. **四大支柱**：Agent 智能化（提采纳率上限）→ 团队协作（扩用户）→ 生态开放（放大覆盖）→ 评估闭环（证进化、防漏出），由**开源社区飞轮**串联。
4. **路线图**：Q0 先修断裂主路径 → Q1 让 agent 变聪明 + 质量守门 → Q2 让团队用起来 → Q3 让生态转起来 → Q4 闭合飞轮，收敛 v2.0 GA。

## 关键取舍原则（开源定位）

规划中每个决策都遵循这些原则（详见 [02 §六](./02-vision-strategy.md)）：

0. **主路径可靠性 > 一切新功能**（Q1 门槛）
1. **采纳率 > 功能数**
2. **本地可跑（Ollama）> 云端能力**
3. **贡献者体验 > 企业特性**
4. **可度量 > 感觉好**
5. **不破坏地基（7 抽象 / 13 包）**
6. **透明治理（公开 RFC / 路线图）**

## 落地建议

1. **先对齐 01 与 02**：现状判断（尤其主路径断裂红线）和北极星达成共识，是后续一切的前提。
2. **Q0 立即启动**：P0 加固不需要等季度规划走完，[07 §三](./07-roadmap-4q.md) 的任务清单可直接转为 issue。
3. **走公开 RFC**：四大支柱的关键设计（异步 Gate 机制、语义记忆选型、市场协议）建议各出一份社区 RFC。
4. **每季度复盘 KPI**：用 [07 §八](./07-roadmap-4q.md) 健康度护栏 + 各季度 KPI 做季度 gate。
