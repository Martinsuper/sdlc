# 02. 愿景与战略

> 版本：v2.0-planning（2026-07-16）
> 承接：[01-产品现状盘点](./01-product-assessment.md)
> 定位：开源社区驱动 · 四季度规划

---

## 一、产品愿景（3 年）

> **让每一个研发团队都拥有一支"懂你项目、会自我进化、可被信任"的 AI 研发梯队 —— 开源、可自托管、越用越懂你。**

拆解三个关键词：

- **懂你项目**：不是通用 copilot，而是通过 3 层记忆真正"读过"你的代码、规范、历史决策，产出贴合本项目上下文的结果。
- **会自我进化**：每一次 Pipeline 都让系统更准 —— 不只是知识更多，而是决策更对（评估闭环 + 反馈回流）。
- **可被信任**：全链路可审计、人工可把关（异步 Gate）、质量可度量（evals）—— 让团队敢把真实生产任务交给它。

---

## 二、北极星指标（North Star）

### 北极星：**周活跃可信 Pipeline 数**（Weekly Trusted Pipelines, WTP）

> 定义：每周成功跑完、且**产物被人类采纳（合入代码 / 通过 Gate / 触发部署）**的 Pipeline 数量。

**为什么是它**：
- 它同时约束了**用量**（跑了多少）和**质量**（被采纳，而非跑完就丢）—— 单看"运行次数"会奖励刷量，加上"被采纳"才对齐真实价值。
- 它天然驱动四大支柱：agent 更聪明 → 采纳率↑；协作更顺 → 团队愿意跑；生态更全 → 覆盖更多技术栈；评估更准 → 信任度↑愿意采纳。
- 它对开源友好：可通过匿名遥测（opt-in）在社区侧聚合，不依赖商业计费数据。

### 输入指标（North Star 的分解驱动因子）

```
周活跃可信 Pipeline 数 (WTP)
├── 活跃团队/仓库数        （广度：多少人在用）
├── 人均周 Pipeline 数      （频度：用得多不多）
├── 产物采纳率              （质量：跑完有没有用 —— 支柱一/四直接影响）
└── 团队协作 Pipeline 占比   （深度：是不是团队在用，而非个人 —— 支柱二影响）
```

## 三、四大战略支柱

四大支柱不是并列的功能包，而是有内在依赖顺序的价值链：

```
        ┌─────────────────────────────────────────────────┐
        │              北极星：周活跃可信 Pipeline           │
        └───────────────────────┬─────────────────────────┘
                                 │
     ┌───────────────┬──────────┴──────────┬────────────────┐
     ▼               ▼                     ▼                ▼
┌─────────┐   ┌─────────────┐      ┌─────────────┐   ┌─────────────┐
│ 支柱一   │   │ 支柱二       │      │ 支柱三       │   │ 支柱四       │
│ Agent    │   │ 团队协作     │      │ 生态开放     │   │ 评估质量     │
│ 智能化   │   │ 与企业化     │      │ 与集成       │   │ 闭环         │
├─────────┤   ├─────────────┤      ├─────────────┤   ├─────────────┤
│提升"采纳 │   │让"团队"能用  │      │让"更多场景" │   │让"变好"可度量│
│率"上限   │   │ 而非个人     │      │ 被覆盖       │   │+ 反哺支柱一  │
└────┬────┘   └──────┬──────┘      └──────┬──────┘   └──────┬──────┘
     │               │                    │                 │
     └───────────────┴────────────────────┴─────────────────┘
        支柱四的评估数据 → 反哺支柱一的 agent 优化（核心飞轮）
```

### 支柱一：Agent 智能化深化 —— *提升产物质量上限*

把 Subagent 从"带工具的单轮 prompt"升级为具备 **规划（Plan）→ 执行（Act）→ 反思（Reflect）→ 协作（Delegate）** 的完整智能体；把记忆从文件柜升级为**语义大脑**。

**核心命题**：产物采纳率是北极星的质量因子，而采纳率的天花板由 agent 智能决定。这是**护城河与差异化的根本来源**。

→ 详见 [03-支柱一](./03-pillar-agent-intelligence.md)

### 支柱二：团队协作与企业化 —— *把用户从个人扩展到团队*

解决 Gate 同步阻塞与纯单机两大瓶颈：异步审批、Web 控制台、可观测 dashboard、自托管服务端、组织级 KB 共享、轻量权限。

**核心命题**：开源项目的留存靠团队采用。让协作从"不可能"变成"顺滑"，是把用户基数从"个人尝鲜"抬到"团队标配"的关键。

→ 详见 [04-支柱二](./04-pillar-collaboration.md)

### 支柱三：生态开放与集成 —— *扩大可覆盖场景*

插件 SDK、模板/Adapter 市场、MCP 工具生态深度打通、A2A 多 agent 协议、与 IDE/CI/IM 的原生集成。

**核心命题**：开源增长引擎是社区共建。市场让"1 个团队写的 Adapter，1000 个团队用"，形成飞轮。

→ 详见 [05-支柱三](./05-pillar-ecosystem.md)

### 支柱四：评估与质量闭环 —— *让"越用越好用"从口号变数据*

evals 数据集、LLM-as-judge、跨版本回归、ROI 量化、上线效果 → 决策的反馈回流学习。

**核心命题**：这是唯一能证明"进化"真实发生的支柱，也是反哺支柱一的数据来源。没有它，agent 优化就是盲改。

→ 详见 [06-支柱四](./06-pillar-eval-quality.md)

## 四、开源社区飞轮

> ⚠️ **飞轮的前置条件：主路径必须先能跑通。** [01 §二·五](./01-product-assessment.md) 已确认端到端 `sdlc run` 当前 100% 失败（P0：temperature 硬编码、错误吞没）。飞轮所有环节都以"Pipeline 能成功运行"为前提 —— 所以路线图把 **Q1 的 P0 稳定性加固**列为一切支柱之前的门槛，而非某个支柱内部的子任务。

支柱三与支柱四共同驱动一个自我强化的社区飞轮，这是开源定位下的核心增长模型：

```
        更多团队采用（支柱二降低门槛）
              │
              ▼
      更多真实 Pipeline 运行
              │
              ▼
   更多 eval 数据 & 反馈（支柱四）───────┐
              │                          │
              ▼                          │ 反哺
      agent 产物质量提升（支柱一）        │
              │                          │
              ▼                          │
      采纳率↑ → 口碑↑ → 更多贡献         │
              │                          │
              ▼                          │
   更多 Adapter/模板/工具进市场（支柱三）─┘
              │
              ▼
      覆盖更多技术栈 → 吸引更多团队 →（回到顶部）
```

**飞轮的启动顺序**（决定路线图排序）：
1. 先让 **agent 变聪明**（支柱一）—— 否则采纳率低，飞轮转不起来。
2. 同时**降低团队门槛**（支柱二）—— 让飞轮有足够的运行样本。
3. 用**评估闭环**（支柱四）把样本变成改进信号。
4. 用**市场**（支柱三）把改进沉淀为可复用资产，放大覆盖。

## 五、目标用户与场景分层

| 层级 | 用户 | 核心场景 | v2.0 主要受益支柱 |
|---|---|---|---|
| **L0 个人开发者** | 单人 / 小项目 | 本地跑通一个需求，`init` 后开箱即用 | 支柱一（更聪明）、支柱三（本地 Ollama） |
| **L1 小团队 maintainer** | 3–10 人开源/内部团队 | 团队共享 KB、异步 Gate 审批、CI 集成 | 支柱二（协作）、支柱三（集成） |
| **L2 平台/工程效能团队** | 维护多仓库、定制 Adapter | 自托管控制台、组织 KB、自定义扩展、ROI 报告 | 支柱二（企业化）、支柱四（度量） |
| **L3 贡献者** | 给 sdlc 本身提 PR | 写 Adapter/Stage/Rule、评估自己的改动 | 支柱三（SDK/市场）、支柱四（evals） |

**优先级**：开源驱动下，**L1 小团队 maintainer 是核心突破口**（决定口碑与留存），L3 贡献者是增长引擎（决定生态活力）。L2 企业化能力做"可选自托管"，不做重销售。

## 六、战略取舍原则（用于路线图决策）

当资源冲突、优先级打架时，按以下原则裁决：

0. **主路径可靠性 > 一切新功能**（Q1 门槛）：在端到端 `sdlc run` 稳定通过、`doctor` 能真实探活之前，P0/P1 加固优先于任何支柱的新特性。断裂的主路径让北极星恒为 0。
1. **采纳率 > 功能数**：能提升产物被采纳率的改进，优先于新增一个 Stage/Adapter。
2. **本地可跑 > 云端能力**：任何新特性默认要能在 Ollama + 单机下跑通，云/SaaS 是增强不是前提。
3. **贡献者体验 > 企业特性**：扩展点的易用性、可测试性优先于 SSO/SCIM 等 IT 采购特性。
4. **可度量 > 感觉好**：新增 agent 能力必须带 eval，用数据证明而非主观判断。
5. **不破坏地基**：新能力通过扩展点/新模块加入，不重写 7 抽象与 13 包的既有契约。
6. **透明治理**：重大方向走公开 RFC，路线图与决策记录开源。

## 七、成功指标体系（KPI 树）

分三层，每层服务不同决策者。各支柱的详细指标见对应文档，此处汇总顶层。

### 7.1 北极星层

| 指标 | 当前基线 | Q1 目标 | Q4 目标 |
|---|---|---|---|
| 周活跃可信 Pipeline 数 (WTP) | 未度量（需先建遥测） | 建立度量 + 首月基线 | 基线 × 5 |
| 产物采纳率 | 未度量 | ≥ 60% | ≥ 80% |
| 团队协作 Pipeline 占比 | ~0% | ≥ 20% | ≥ 50% |

### 7.2 支柱层（North Star 驱动因子）

| 支柱 | 代表指标 | Q4 目标 |
|---|---|---|
| 一 · Agent 智能 | Stage 产物一次通过率（eval 判定） | ≥ 85% |
| 一 · 语义记忆 | KB 相关上下文命中率 | ≥ 75% |
| 二 · 协作 | 异步 Gate 平均审批时长 | < 4h |
| 二 · 协作 | 接入 Web 控制台的团队数 | ≥ 50 |
| 三 · 生态 | 市场可用 Adapter/模板数 | ≥ 100（含社区贡献） |
| 三 · 生态 | 社区贡献的扩展占比 | ≥ 40% |
| 四 · 评估 | 覆盖 eval 的 Stage 占比 | 100% |
| 四 · 评估 | 每次 release 附带回归报告 | 100% |

### 7.3 健康度层（护栏指标，不能倒退）

| 指标 | 约束 |
|---|---|
| **端到端冒烟通过率** | **= 100%**（每次 release 前 `sdlc run` 全 Profile 真实补全冒烟必须全绿 —— 这是 GA 时缺失、导致 P0 漏出的护栏） |
| 测试覆盖率 | ≥ 90%（不低于 GA） |
| 单需求 LLM 成本 | 不高于 GA 基线的 1.2× |
| 本地（Ollama）可跑通的 Profile 占比 | 100% |
| P0/P1 缺陷 | 每 release < 3 |
| 文档同步率（新特性附文档） | 100% |

## 八、风险与假设

| 风险 | 等级 | 缓解 |
|---|---|---|
| agent 智能化提升有限（模型天花板） | 高 | 用评估闭环快速验证，small win 增量交付，不押单一大改 |
| 团队协作服务端引入运维复杂度，吓退开源用户 | 中 | 服务端做成"可选、单二进制、SQLite 起步"，CLI 永远能独立跑 |
| 遥测触及隐私顾虑（开源社区敏感） | 高 | 严格 opt-in、本地聚合、开源遥测代码、匿名化 |
| 市场缺乏冷启动内容 | 中 | 官方先填充 top 20 Adapter/模板，再开放社区提交 |
| 语义记忆引入向量库依赖，违反"本地可跑" | 中 | 选可嵌入的本地方案（如 sqlite-vec），不强依赖外部向量服务 |
| 四支柱并行导致资源分散 | 中 | 路线图按飞轮启动顺序排期，每季度单主线 + 辅线 |

## 九、本文小结

- **愿景**：懂你项目、会自我进化、可被信任的开源 AI 研发梯队。
- **北极星**：周活跃可信 Pipeline 数 —— 同时约束用量与质量。
- **四大支柱**：Agent 智能化（提上限）→ 团队协作（扩用户）→ 评估闭环（证进化）→ 生态市场（放大覆盖），由社区飞轮串联。
- **取舍原则**：采纳率优先、本地可跑、贡献者友好、可度量、不破坏地基、透明治理。
