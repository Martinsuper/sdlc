# 阶段：状态查看（status）

扫描当前项目 `.sdlc/` 下的阶段产物，汇总研发进度到哪一步。纯只读，不产生任何文件。

## 输入

- 无参数：汇总全部阶段。
- 带参数（如 `design` / `review` / `deploy`）：只展示该阶段。
- 带具体文件路径：读取并展示该产物摘要。

## 前置检查

- 无需探测项目画像。
- 若项目根没有 `.sdlc/` 目录 → 告诉用户当前项目还没走过任何 SDLC 阶段，建议从 `sdlc clarify` 或 `sdlc design` 开始。

## 执行

扫描 `.sdlc/` 下的数字前缀阶段目录：

```bash
ls -d .sdlc/*/ 2>/dev/null
find .sdlc -maxdepth 2 -name "*.md" 2>/dev/null | sort
```

对每个找到的产物，读顶部元信息块拿到 **状态** 字段，推断阶段进展：

- `00-clarify/` → 需求澄清（已澄清 / 待确认）
- `01-design/` → 方案设计（待评审 / 已评审）
- `02-review/` → 设计评审（通过 / 有条件通过 / 不通过）
- `03-code/` → 编码（有 impl-notes 视为已实现说明）
- `04-test/` → 测试（看测试计划与结果）
- `05-deploy/` → 上线计划（待评审 / 已通过 / 已上线）

多需求（`.sdlc/<slug>/...` 子目录）时，按需求分组展示。

## 产出

只在终端输出摘要，不写文件。格式示例：

```
📋 SDLC 进度 —— <项目名>
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 00 需求澄清   .sdlc/00-clarify/00-requirements.md      已澄清
✅ 01 方案设计   .sdlc/01-design/00-design.md             已评审
⚠️ 02 设计评审   .sdlc/02-review/00-review.md             有条件通过（2 个 P1）
⬜ 03 编码       —— 尚未开始
⬜ 04 测试       —— 尚未开始
⬜ 05 上线计划   —— 尚未开始
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
下一步建议：处理评审的 2 个 P1 风险，或进入 code 阶段。
```

## 交接

根据进度给一句下一步建议（哪个阶段该做了、有无阻塞风险），但不自动执行——等用户明确指令。
